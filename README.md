# TauntKey v0.9 — штатная задача насмешки на F

Эта версия вызывает `TASK_TAUNT_ACTOR_IN_PLACE(player, target, 3.0f)`.
Ручной выбор PLAYER_TAUNT_GENERIC/CRIMINAL/LAW и прямые вызовы речи удалены.
Обработка задачи, анимации и речи остаётся движку игры. Исполнение этой задачи
на управляемом игроке пока не подтверждено внутриигровой проверкой.

## Установка

Закройте игру. Замените `TauntKey.red` и `TauntKey.ini` рядом с RDR.exe.
RedHook 0.8 должен быть установлен. Не оставляйте вторую копию плагина.

Загрузите сохранение, подойдите к NPC в пределах 8 м и нажмите F.
Приоритет: игровая цель, текущий собеседник, затем ближайший живой NPC-человек.
Для поиска плагин поднимается по GET_OBJECT_OWNER к корневому layout и создаёт
итератор актёров. Циклы и чрезмерная глубина владения отклоняются. Итератор
освобождается; обход ограничен 8192 объектами и уступает кадр каждые 128 объектов.
Поиск по расстоянию пока не проверяет стены и направление взгляда.
Если цели нет, действие пропускается и причина пишется в лог.

F6/F8 не нужны. F может также выполнять штатное действие игры — подавление
этого действия ещё не реализовано. При паузе, кат-сцене, уже идущей речи и
в течение cooldown запрос не отправляется. Честь не меняется. EXE не патчится,
флаги насмешки напрямую не меняются, управление игроком не отключается.

## Лог

`TauntKey.log` рядом с плагином, запасной путь `%TEMP%\TauntKey.log`.
Лог содержит ATTACH v0.9, SCRIPT START, KEY, TARGET, REQUEST
TASK_TAUNT_ACTOR_IN_PLACE, длительность запроса и наблюдение текущей речи.
`TARGET raw` показывает исходные результаты двух игровых функций; SEARCH — корневой
layout, число просмотренных актёров и выбранного NPC. `REQUEST` означает только
вызов задачи, а не доказательство её исполнения.
Если звука/жеста нет, пришлите лог. Принудительных дисковых сбросов нет.

## Настройки

Key=70 — F, RadiusMetres=8, TaskSeconds=3, CooldownMs=4000.
Прежние TaskMode/GenericContext больше не читаются. Изменения — после перезапуска.

## Проверено статически

В предоставленном RDR.exe native 030FB1FA зарегистрирован на RVA C1BA30;
адаптер C1DB10 передаёт actor/target и читает третий аргумент как float.
Построитель C14AE0 создаёт тип с именем TASK_TAUNT_ACTOR_IN_PLACE (C16C40).
AI_GET_ACTOR_CONVERSATION_TARGET (D8C8BEA1) принимает actor и возвращает
script handle собеседника через обработчик C46E30. GET_TARGET_ACTOR — 0EF7427B.

Дополнительно найдено: SET_ACTOR_SHOULD_TAUNT (199600FA) меняет бит 3
по смещению 41F через actor+40; именно его читает ConditionTauntInsteadOfGreet.
Одна установка этого флага не запускает действие, поэтому плагин его не трогает.

Сборка: ./build.sh (MinGW-w64 x64 C++17). Проверяются PE x64, системные
зависимости DLL и соответствие экспортов предоставленному RedHook.
Загрузка игры в этой облачной среде недоступна. Воспроизведение в v0.6
подтверждено пользователем только для прямого вызова CRIMINAL; это не является
проверкой задачи, используемой в v0.7.

## Исправление v0.8 по логу пользователя

В логе v0.7 все попытки имели requested=0: игровые функции не выделяли цель.
Задача насмешки не вызывалась ни разу, поэтому этот лог ещё не проверяет её работу
на Джоне. Добавлен поиск ближайшего NPC. Предыдущий подход с
GET_LAYOUT_FROM_OBJECT был ошибочным: обработчик в этой сборке фактически
возвращает исходный handle, а GET_OBJECT_OWNER действительно читает родителя
по +0x1C (RVA 22D140). Локальный тест owner_root_test проверяет цепочку владения,
самоссылку, цикл и ограничение глубины. При отсутствии цели задержка повторной
попытки теперь 250 мс вместо четырёх секунд.

Проверены сборка и тест цепочки владения; наличие NPC в новом поиске и
исполнение задачи в самой игре ещё требуют проверки.

## Исправление v0.9

В v0.8 корень находился (root=1 type=1), но все обходы возвращали scanned=0.
Создание итератора устанавливает владельца, но не область поиска. Добавлен
ITERATE_IN_LAYOUT(iterator, root), затем фильтр Actor и ITERATE_EVERYWHERE.
В предоставленном EXE ITERATE_IN_LAYOUT через RVA 230220 вызывает 2EBFB0:
записывает область в iterator+70 и включает bit 2 в +FC. Конструктор
CREATE_OBJECT_ITERATOR (226990) в конце явно очищает этот бит.
ITERATE_EVERYWHERE (2301E0) только обнуляет +A4 и область не устанавливает.
Поэтому прежняя последовательность не была полноценной настройкой итератора.
Новый лог SEARCH iterator=... scope=... configured показывает завершение настройки.
Вызов насмешки и правила выбора игрового/ближайшего NPC не изменены.
Результат этого исправления в игре ещё требует проверки; задача пока не подтверждена.
