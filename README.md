# TauntKey v0.6 — F + файловая диагностика

## Установка

Закройте игру. Замените старые `TauntKey.red` И `TauntKey.ini` двумя файлами из этого архива в папке с `RDR.exe` и RedHook 0.8. Не оставляйте вторую копию плагина под другим именем.

Запустите игру, загрузите сохранение за Джона, кратко нажмите **F** (в режиме речи NPC поблизости больше не требуется). Подождите 3 секунды. Никакие F6/F8 для проверки не нужны.

Рядом с плагином создаётся **TauntKey.log**. Если папка защищена от записи, запасной путь — **%TEMP%\TauntKey.log** (вставьте его в адресную строку Проводника). Лог дописывается с временными метками. Пришлите его после проверки. Если файла нет в обоих местах, сообщите именно об этом: DLL могла вообще не загрузиться, и диагностировать игровые natives тогда рано.

## Что фиксирует лог

- ATTACH: Windows загрузила DLL; версия и PID.
- BIND OK либо BIND FAILED: совместимость экспортов RedHook.
- REGISTERED, SCRIPT START: регистрация и фактический запуск скрипта.
- HEARTBEAT раз в 10 секунд: скрипт продолжает работать, активность окна.
- KEY: нажатие F через callback и/или резервный GetAsyncKeyState.
- SKIP: точная причина пропуска (пауза, кат-сцена, речь, cooldown, отсутствие NPC).
- SEARCH/CANDIDATE: layout, iterator, найденные кандидаты, результат поиска.
- CONTEXT: ID контекста в текущей игре, enum модели и ответ modelHasPhrase. `id=-1` означает отсутствие контекста, `modelHasPhrase=0` — отрицательный ответ движка для модели.
- ATTEMPT: возврат запроса и его длительность; подробное логирование каждого native удалено.
- REQUEST: запрос речи и выбранный контекст. Возврат из native НЕ доказывает, что звук проигран.
- OBSERVE в течение 2 секунд: ответ IS_ANY_SPEECH_PLAYING. Это индикатор речи вообще, а не доказательство конкретной реплики.

Лог не содержит клавиш, отличных от назначенной F, аудиозаписей или данных сохранений. Он локальный, автоматически никуда не отправляется. Запись идёт через обычный файловый кеш Windows. Принудительные FlushFileBuffers удалены; устойчивость последней строки к отключению питания не гарантируется.

## Исправление по пользовательскому логу v0.2

Клавиша и script fiber работали, однако все шесть попыток поиска возвращали `scanned=0`. Запрос речи ни разу не выполнялся. На попытку уходило около 0.7 секунды; записи до/после каждого native вместе с принудительным FlushFileBuffers создавали десятки синхронных сбросов. В одном случае опрос и задержанный callback запускали поиск дважды.

В v0.3 удалены принудительные сбросы и трассировка каждого native. Прямой запрос речи больше не запускает поиск NPC и не зависит от его результата. Активация идёт только по фронту нажатия из GetAsyncKeyState; callback больше не запускает повторную попытку. Исправление устраняет найденные программные причины пропуска речи и лишней дисковой задержки. Фактическую доступность реплики ещё нужно проверить в игре.

## Механизм речи

Перед запросом речи v0.6 проверяет загруженную таблицу контекстов и вызывает `CAN_ACTOR_ENUM_PLAY_SPEECH_CONTEXT` для модели игрока. Порядок выбора: PLAYER_TAUNT_GENERIC → PLAYER_TAUNT → PLAYER_TAUNT_CRIMINAL → PLAYER_TAUNT_LAW. Выбирается первый существующий контекст с положительным результатом modelHasPhrase. Приветствия только диагностируются, но не выбираются.

В пользовательском логе v0.5: GENERIC имел ID 424 и modelHasPhrase=0; CRIMINAL — ID 423 и 1; LAW — ID 425 и 1. Старый фильтр исключал обе доступные насмешки, и REQUEST не происходил. В v0.6 этот фильтр исправлен; добавлен регрессионный тест по фактическим данным лога. Семантика реплик CRIMINAL/LAW зависит от контекста (обращения к преступникам/закону); это ещё не точное отделение всех грубых приветствий от чести.

Таблица читается через ReadProcessMemory, без патчей и внутренних вызовов по адресам. Чтение разрешено только при совпадении PE timestamp, SizeOfImage и 24 байт обработчика с предоставленным EXE. Для другой сборки в логе будет отказ проверки. За один запрос таблица считывается одним блоком, чтобы не делать тысячи системных вызовов.

Исправление v0.5: сравнение с таблицей теперь использует промежуточный Jenkins hash без финализации (как функция игры RVA C7570). В v0.4 использовался финализированный hash, поэтому все `id=-1` были ложными отрицательными результатами. Они не доказывают отсутствие реплик. Добавлен отдельный регрессионный тест `g++ -std=c++17 tests/speech_hash_test.cpp -o /tmp/speech_hash_test && /tmp/speech_hash_test`.

Вызов речи заменён на `SAY_SINGLE_LINE_CONTEXT` (31BAF169) с найденным числовым ID: обработчик игры выставляет флаги контекстного воспроизведения, отсутствующие в прежнем строковом вызове. Подтверждено по RVA E343B0–E3459A; третий аргумент — необязательная цель (-1), аргументы 7/8 — резервные контексты (-1), девятый — номер реплики (0 = выбор движка). Это исправление кода, но внутриигровой звук ещё не проверен.

По результату лога v0.3: три запроса вернулись за 0 мс, один интервал IS_ANY_SPEECH_PLAYING был положительным, но пользователь звука не слышал. Нельзя утверждать, что этот индикатор относится к нашей реплике. Причина отсутствия звука ещё не установлена; v0.4 — диагностика наличия контекста/реплик, не подтверждённый исправленный звук.

Для выбранного контекста используется `SAY_SINGLE_LINE_CONTEXT`. Старая AI-задача могла не исполняться на управляемом персонаже. Новый запрос также требует проверки в игре: наличие контекста в EXE не гарантирует доступность нужной реплики в текущем состоянии. Честь плагин не записывает, код игры не патчит.

В режиме речи выбор NPC не выполняется: цель для нового context-native пока не выбирается. Ответ NPC, жест и поворот к нему в этом режиме не реализованы. Не проверяются стены и направление взгляда. Штатное действие F не подавляется.

## Настройки

Настройки читаются при загрузке DLL; после изменения перезапустите игру.

- `Key=70`: F. Другие клавиши плагин не назначает. Если F конфликтует, можно выбрать другой Windows virtual-key code.
- `RadiusMetres=8`: радиус только старого режима TaskMode=1, диапазон 1–20. Проблема пустого итератора в этом режиме ещё не устранена.
- `CooldownMs=4000`: задержка, диапазон 1000–30000.
- `GenericContext`: устаревшая настройка; в v0.5 контекст выбирается автоматически после проверки доступности.
- `TaskMode=0`: прямой запрос речи; `1`: прежняя AI-задача с float-параметром `TaskSeconds=3` для сравнения.

## Сборка и проверенные границы

`./build.sh` с MinGW-w64 x64 C++17. Получается `dist/TauntKey.red`. Дополнительные DLL компилятора не требуются. Экспорты RedHook 0.8 разрешаются динамически.

Проверены регрессионные тесты хеширования и выбора по данным пользовательского лога, сборка Windows x64, системные зависимости DLL, наличие требуемых экспортов в предоставленном RedHook, отсутствие импорта FlushFileBuffers и целостность ZIP. Запуск игры и фактическая запись логов на Windows в этой среде недоступны; внутриигровое воспроизведение не подтверждено.
